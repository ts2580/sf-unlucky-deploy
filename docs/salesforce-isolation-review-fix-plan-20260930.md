# Salesforce 사용자 격리와 연결 저장 결함 수정 계획

리뷰에서 지적한 사용자 컨텍스트 혼선, 연결 교체 경쟁 조건, 동시 등록 오류, 재인증 상태 오판, 소스 ZIP의 런타임 파일 포함을 수정한다. GPT-6 Luna high 에이전트가 구현하고 주 에이전트가 경쟁 조건과 산출물을 독립 검토한다.

## 현재 코드에서 확인한 사항

- 큐의 후속 작업은 직전 작업의 완료 콜백에서 실행되며 enqueue 당시 비동기 컨텍스트를 별도로 보존하지 않는다.
- Salesforce 연결은 재등록 때 ID를 유지하고, 인증 URL 읽기·갱신·재인증 표시는 ID만 조건으로 사용한다.
- 최초 등록의 기존 행 조회·ID 결정·암호화·저장은 분리된 DB 호출이다. 저장소에는 트랜잭션을 직렬화하는 `DatabaseExecutor.transaction`이 이미 있다.
- 인증 복원 오류 중 저장 오류를 제외한 모든 오류가 재인증 필요 상태로 기록된다.
- `.sfud-local`은 Git 제외 대상이 아니다. 현재 소스 ZIP에서 실행 DB·WAL·SHM과 Git 캐시 SQLite 파일 이름을 확인했다. DB 내용이나 세션 값은 출력하지 않았다. 실행 DB는 Git 추적 상태가 아니다.

## 수정 순서와 회귀 기준

### 1 작업 큐의 실행 컨텍스트 고정

- enqueue 시점의 비동기 컨텍스트를 캡처하고 해당 작업의 전체 비동기 실행에 복원한다. 비교·Dry-run·실제 배포의 공통 큐에 적용한다.
- `AsyncResource.bind` 등 Node 내장 기능 또는 명시적인 소유자 래퍼를 사용하되, 요청에서 이미 고정한 연결 정보도 보존한다. 새 사용자 ID만 설정하면서 기존 연결 고정을 초기화하지 않는다.
- 인증 컨텍스트가 없는 작업은 직전 사용자의 컨텍스트를 물려받지 않는다. LOCAL 모드와 CLI의 컨텍스트 없는 큐 사용은 유지한다.
- 실제 큐와 지연 제어 Promise를 사용해 A 실행 중 B 대기, 같은 별칭의 서로 다른 인증, 컨텍스트 없는 후속 작업, 복수 실행 슬롯을 검증한다. 실제 `UserSfClient` 인증 복원 대상이 소유자에 맞는지도 확인한다.

### 2 연결 세대와 경쟁 조건 방어

- DB 마이그레이션으로 연결 세대를 저장한다. 기존 ID와 암호문은 유지하며 기존 행은 초기 세대로 이전한다. 재등록마다 세대를 바꾸고 일반 갱신 토큰 저장은 재등록 세대를 바꾸지 않는다.
- 별칭 고정값을 연결 ID와 세대의 조합으로 확장한다. 인증 URL 읽기는 예상 세대와 같은 행만 사용하고, 불일치하면 `ORG_IDENTITY_CHANGED`로 중단한다.
- 갱신 토큰 저장과 재인증 상태 변경은 소유자·ID·세대 조건을 함께 사용한다. 교체된 새 연결을 이전 작업이 덮어쓰거나 재인증 상태로 만들 수 없어야 한다.
- Org identity 스냅샷·검증·캐시 경로도 점검한다. 캐시에서 가져온 이전 identity와 새 인증이 섞이지 않도록 세대 정보와 작업 고정을 연결한다. 기존 LOCAL identity와 저장 작업의 호환성을 명시적으로 유지한다.
- identity 확인 후 인증 복원 직전 재등록, 인증 복원 후 제출 전 재등록, 실행 중 이전 토큰 갱신 완료, 이전 인증 오류의 지연 도착을 제어 가능한 경쟁 테스트로 확인한다. 검증된 Org와 다른 Org의 인증으로 제출되는 호출이 없어야 한다.

### 3 최초 등록의 원자성 확보

- 기존 행 조회부터 ID·세대 결정, 암호화, INSERT 또는 UPDATE, 반환 행 조회까지 한 트랜잭션으로 처리한다.
- 트랜잭션 콜백 안에서는 전달받은 DB 핸들을 사용한다. 같은 `DatabaseExecutor`에 다시 작업을 넣어 교착 상태를 만들지 않는다.
- 동일 사용자·별칭의 최초 등록과 재등록을 `Promise.all`로 겹쳐 실행한다. 한 행만 남고 최종 행의 identity·세대·암호문이 같은 등록 요청에 속하며 복호화가 성공해야 한다.
- 다른 사용자·같은 별칭의 등록은 서로 격리되어야 한다. 이전 DB 마이그레이션 후 기존 암호문 복호화도 확인한다.

### 4 일시적 CLI 실패의 재인증 오판 방지

- CLI 실행 오류와 확정적인 인증 만료·철회를 구분할 수 있는 좁은 오류 분류를 적용한다. 구조화된 CLI 오류 코드·이름을 우선하고 일반 실패 문구 전체를 넓게 매칭하지 않는다.
- 네트워크 장애, 시간 초과, 취소, 실행 파일 부재, JSON 오류, 분류 불가능한 실행 실패는 연결 상태를 유지한다.
- 확정적인 인증 실패만 현재 세대에 한해 `REAUTH_REQUIRED`로 변경한다. Org 목록에서 일시 실패한 연결은 다음 조회에서 다시 시도할 수 있어야 한다.
- 일시 실패 후 복구, 확정 인증 실패, 새 연결로 교체된 뒤 도착한 이전 실패를 각각 검증한다. CLI 실패 분류 테스트에는 비밀값이 노출되지 않는지도 포함한다.

### 5 런타임 파일 제외와 소스 ZIP 재생성

- `.gitignore`에 `.sfud-local/`을 추가하고 생성된 소스 아카이브도 Git 변경 목록에서 제외한다.
- 실행 중인 실제 `.sfud-local` DB·WAL·SHM은 보존한다. 정리는 소스 배포 후보 및 ZIP 내부에서 수행한다.
- 재현 가능한 소스 압축 절차를 마련한다. 현재 작업 트리의 소스와 설정 예시는 포함하고 `.env`, 런타임 디렉터리, DB·WAL·SHM·저널, 비밀키, 캐시, 빌드 결과, 의존성, 문서, 이전 아카이브를 제외한다. `.env.example`은 유지한다.
- 전체 수정 후 `sf-unlucky-deploy-source-20260929.zip`을 깨끗한 산출물로 교체한다. 오염된 ZIP의 복사본을 배포 디렉터리에 남기지 않는다.
- ZIP CRC, 금지 경로 부재, 주요 수정 소스 포함 및 원본과 바이트 일치, SHA-256을 확인한다. DB 내용이나 인증 URL을 보고서에 기록하지 않는다.

## 검증과 역할 분담

1. Luna 에이전트는 현재 dirty worktree를 보존하며 다섯 항목을 구현하고 각 결함을 재현하는 테스트를 추가한다. 실행 서버·실제 DB·환경변수는 직접 변경하지 않는다.
2. 주 에이전트는 큐 컨텍스트, 세대 검증의 읽기와 쓰기 경쟁 조건, 캐시 경로, 압축 필터를 검토하고 필요한 보완을 요청한다.
3. 집중 회귀 테스트 후 전체 Vitest, 타입 검사, 정적 검사, 잠금 파일 검사, `npm run build`를 실행한다. 인증 API 응답이나 공통 런타임에 영향이 있으면 기존 OAuth·인증 E2E도 확인한다.
4. 소스 ZIP은 구현과 최종 검증이 끝난 최신 소스로 재생성한다.
5. 결과 보고는 코드·로컬 테스트·아카이브 검증의 범위를 구분한다. 실제 Salesforce Org 배포나 갱신 토큰 연동을 수행한 것처럼 보고하지 않는다.

커밋·push·PR·병합과 실제 Salesforce 변경은 포함하지 않는다. DB 마이그레이션은 테스트 DB에서 검증하며 실행 서버 반영은 별도 상태로 보고한다.
