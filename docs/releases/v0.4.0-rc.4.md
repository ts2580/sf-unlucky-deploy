# sf-unlucky-deploy v0.4.0-rc.4

npm 시험 배포 대상: `@trstyq/sf-unlucky-deploy@0.4.0-rc.4`, dist-tag `next`.

## 변경 사항

- 개인용 `LOCAL=true`와 접속 주소 분리. 원격 Linux 서버에서도 서버 OS 계정의 Salesforce CLI 인증을 사용하는 개인용 실행 지원.
- 원격 개인용 접속 비밀번호 `SFUD_ACCESS_PASSWORD` 추가. 계정 생성 없이 비밀번호로 접속하고 모바일에서도 로그아웃 지원.
- 원격 주소·공개 Origin·프록시를 사용하는 개인용 실행에서 비밀번호 필수 검사. 기존 루프백 개인용은 비밀번호 없이 사용 가능.
- 비루프백 HTTP에서 UUID 생성 오류로 dry-run·직접 배포 요청이 중단되던 문제 수정. 보안 난수 기반 UUID v4 대체 생성 및 재시도 키 유지 검증 추가.
- Git 가져오기의 DX 프로젝트 자동 탐색 복원. 루트 또는 하위 단일 프로젝트 자동 선택, 다중 후보 선택 및 배포 브랜치의 실제 프로젝트 경로 저장·커밋 재확인 추가.
- 계정 연결 별칭을 사용하는 등록 브랜치의 저장소 식별 개선. 별칭과 저장소 이름을 함께 표시하고 호스트·전체 저장소 경로·프로젝트 경로 보존.
- 비밀번호 설정·변경·제거 시 기존 세션 폐기, 서로 다른 보호 설정의 프로세스 간 세션 공유 차단, 로그인 실패 횟수·CSRF 검사 유지.
- Windows 임시 작업 폴더의 잠금 오류 정리 재시도 및 실행 결과 보존, Git 긴 경로 지원 보강.
- Git 연결 별칭 저장·등록 브랜치 표시 연동, 연결 화면과 메타데이터 비교·선택 조작 개선.
- `sfud setup` 최초 설정 안내와 `sfud doctor` 읽기 전용 점검 추가. 기존 암호화 키·설정 보존, 비대화형 종료와 JSON 진단 지원.
- 사용자별 배포 설정 저장·불러오기·삭제 추가. 저장한 소스·대상과 Org identity를 다시 검증하고 Git 준비는 명시적으로 실행.
- 배포 직전 실제 Git 커밋·프로젝트 경로, 대상 Org, 컴포넌트·테스트·검증 결과 확인 화면 추가.
- 구조화된 오류 원인과 다음 조치, 민감정보를 제거한 상세 복사, 연결 설정 이동 후 선택 복귀 지원.
- 실행 기록의 작업 URL과 새 작업 설정 복원 추가. 응답을 받지 못한 제출은 원래 요청 ID로 조회·재시도하며 Org 대상 변경과 중복 제출 방지.
- 사용자·탭별 선택 초안의 자동 저장과 명시적 복원 추가. 24시간 만료, 저장 순서 검사와 브라우저 임시 보관으로 새로고침·다중 탭 충돌 처리.
- 비교·배포 소스 병렬 준비 중 한쪽이 실패해도 다른 쪽의 파일 쓰기가 끝난 후 작업 종료. 소스 사용권·작업 폴더가 먼저 해제되는 경쟁 상태 수정.
- Fastify 및 하위 의존성 잠금 파일 갱신, 시작 안내와 기능별 사용·운영 문서 분리, 환경설정 키 설명 정리.

## 설치 및 전환

registry 발행 완료 후 설치:

```bash
npm install --global --allow-scripts=sqlite3 @trstyq/sf-unlucky-deploy@0.4.0-rc.4
sfud --version
```

Node.js 22.19.0 이상, Salesforce CLI v2와 Git 필요. 기존 RC3는 유지하며 npm `latest` 이동 없음.

처음 설정하는 경우 `sfud setup`, 기존 설정 점검은 `sfud doctor` 사용. `sfud doctor --json`은 자동화용 결과 제공.
업그레이드 시 DB 마이그레이션 47·48로 배포 설정과 초안 저장 테이블 추가. 기존 키와 데이터는 유지하며,
업그레이드 전 데이터 디렉터리와 홈 설정을 백업하고 이전 버전 복귀 시 함께 복원 필요.

같은 PC에서 사용하는 개인용은 `LOCAL=true`, `SFUD_UI_HOST=127.0.0.1`로 실행.
공개 Origin·신뢰 프록시·접속 비밀번호는 사용하지 않으면 주석 처리 또는 제거. 홈 설정과 OS 환경변수도 확인 필요.

원격 개인용은 설정 폴더(`sfud config path`)의 `secrets.env`에 `SFUD_ACCESS_PASSWORD`를 12~128자로 설정한 뒤 실행:

```bash
LOCAL=true sfud ui --host 0.0.0.0 --allow-remote --no-open
```

이전 버전에서 `LOCAL=true`가 무시하던 원격 주소·공개 Origin·프록시 설정이 이번 버전부터 적용됨.
해당 설정이 남아 있고 비밀번호가 없으면 시작 오류 발생. 내 PC 전용은 원격 설정 제거, 원격 개인용은 접속 비밀번호 설정 필요.
Git·Salesforce 인증 저장용 공통 암호화 키 `SFUD_TOKEN_SECRET`은 기존 값 유지. 접속 비밀번호와 용도 구분.
인터넷 공개 시 HTTPS 프록시 사용. Salesforce CLI의 새 브라우저 OAuth 연결에는 별도 콜백 포트 전달 필요.
