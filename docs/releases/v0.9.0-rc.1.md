# sf-unlucky-deploy v0.9.0-rc.1

Git·로컬 프로젝트·Salesforce Org의 메타데이터 비교를 중심으로 안내와 모듈 구조를 정리한 0.9.0의 첫 RC. canary 기반 GitHub prerelease 및 npm `next` 발행 대상.

## 주요 변경 사항

- README를 비교 대상별 활용 사례, Git 브랜치 선택, 메타데이터 diff 확인, CLI 비교 리포트 순서로 재구성. 검증·배포는 비교 결과를 Org에 반영할 때 사용하는 후속 기능으로 안내.
- 웹 UI의 실제 배포는 사전 Dry-run 없이 선택한 테스트 수준으로 바로 제출. Salesforce에서 요구하는 테스트는 실제 배포 과정에서 실행.
- 명시적인 Dry-run 후 승인 배포 경로 유지. 검증한 파일·Org·테스트 계획 등의 적격성을 확인하고 검증 ID로 Quick Deploy.
- Git·소스·비교·배포·인증의 책임 분리. Git 구현은 `SourceProvider`로 연결하고 CLI 출력·실행 로직, HTTP 인증·세션 저장, UI workflow 경계 분리.
- `DeploymentStateMachine`으로 상태 전이 판단을 모으고 기존 상태 종류·의미 및 저장소의 트랜잭션·동시성 검사 유지.
- 모듈 공개 진입점·의존 방향·순환·브라우저의 서버 코드 참조 검사 추가. 기존 CI의 `npm run check`에서 실행.
- [0.8.0 변경](v0.8.0.md)의 저장소 등록·브랜치 선택 분리, 최신 커밋 비교, Apex 테스트·초안 복원·비교 스크롤 개선 포함. npm 11.4의 tar 6 호환 수정 유지.

## 설치 및 전환

npm 발행과 registry 검증 완료 후 일반판 설치:

```bash
npm install --global --allow-scripts=sqlite3 @trstyq/sf-unlucky-deploy@0.9.0-rc.1
sfud --version
sfud ui
```

시험판 채널을 따라가려면 `@next` 사용. 정식 `latest` 승격은 별도 진행.
Node.js 22.19.0 이상, Salesforce CLI v2와 Git 필요.

업데이트 전 `sfud stop`으로 실행 중인 UI를 종료하고 홈 설정·DB 백업. 기존 설정, SQLite 테이블·DB 버전, 암호화 키와 저장된 인증정보 형식 유지. 인증 라이브러리와 신규 의존성 추가 없음. 공개 CLI 옵션과 HTTP 경로 유지. 내부 소스 경로는 모듈별로 이동.

SQLite 포함 Windows x64 번들의 예정 버전은 `0.9.0-rc.1.win32-x64.1`. 일반판 Release tarball 확정 후 원본 커밋·SHA-256을 고정하여 별도 검증·발행. 일반판과 Windows 번들의 발행 상태는 각각 확인.

## 검증과 발행

canary PR을 사용자가 병합한 뒤 최신 canary 커밋에 annotated tag `v0.9.0-rc.1` 생성. GitHub Release 워크플로에서 타입·단위·브라우저 검사와 동일 tarball의 Linux Node 22.19/24, Windows Node 24, macOS ARM64 Node 24 설치·CLI·UI·SQLite·재시작 검사 수행.

검증한 tarball·SHA-256·SBOM·manifest를 GitHub prerelease에 첨부하고 동일 tarball을 npm `next`로 발행. registry tarball의 바이트 일치 확인 후 일반판 발행 완료로 보고. Windows 번들은 해당 원본 Release를 입력으로 별도 생성·검증.

이 문서는 발행 준비 안내이며 발행 완료 기록은 아님. Salesforce 동작 검증은 fixture 기반이며 실제 Org 배포는 수행하지 않음.
