# sf-unlucky-deploy v0.1.0

Salesforce org와 로컬 DX 프로젝트의 메타데이터를 비교하고, 동일한 staging payload로 check-only 검증까지 수행하는 첫 프리뷰 릴리즈다.

## 주요 기능

- org ↔ org, local ↔ org, local ↔ local 메타데이터 비교
- Apex, XML, LWC, Aura 파일의 컴포넌트 단위 차이와 HTML 리포트
- staging payload SHA-256 고정 및 Salesforce dry-run 우선 배포 흐름
- Apex 테스트 자동 선택과 명시적 test level 지원
- React 기반 반응형 셀프 호스팅 웹 콘솔
- SQLite 사용자, 세션, 감사 이벤트, 비교 및 배포 작업 상태 저장
- 단일 배포 큐와 중단 작업의 `RECONCILE_REQUIRED` 처리

## 설치

GitHub Release에서 `sf-unlucky-deploy-0.1.0.tgz`와 `SHA256SUMS`를 내려받고 체크섬을 확인한다.

```bash
sha256sum --check SHA256SUMS
npm install --global --allow-scripts=sqlite3 ./sf-unlucky-deploy-0.1.0.tgz
sfud --version
```

실행에는 Node.js 20.19 이상과 Salesforce CLI v2가 필요하다. `sqlite3` native binding 설치 스크립트만 명시적으로 허용하며, 다른 의존성 스크립트는 허용하지 않는다.

## 안전 기본값

- `deploy`는 `--execute`가 없으면 항상 Salesforce check-only만 수행
- 비교 후 staging payload가 바뀌면 실제 배포 차단
- destructive manifest 자동 생성 및 삭제 미지원
- Salesforce access token, refresh token, SFDX auth URL 저장 및 출력 차단
- 웹 로그인 IP·계정 제한, CSRF, 프로젝트 allowlist, SQLite 파일 권한 제한 적용

## 알려진 제한

- 웹 콘솔의 실제 배포 승인 버튼은 아직 비활성화 상태
- SQLite와 단일 프로세스 큐를 사용하므로 다중 인스턴스 수평 확장 미지원
- Salesforce CLI 인증과 org 별칭은 실행 호스트에서 별도로 준비 필요
- 전체 org 범위가 아닌 manifest 기반의 명시적 배포 범위 사용 권장
