# sf-unlucky-deploy v0.2.0

메타데이터 비교 결과에서 배포 대상을 직접 구성하고, Dry-run부터 실제 Salesforce 배포까지 진행 상태를 확인할 수 있도록 웹 콘솔의 배포 흐름을 확장한 릴리즈다.

## 주요 변경 사항

- Salesforce CLI가 지원하는 전체 메타데이터 유형의 동적 조회 및 비교
- 비교 검색과 독립적인 배포 대상 선택, source-only manifest 생성
- 설정 페이지의 임시 DX 프로젝트 업로드 및 요청별 격리 작업공간
- Dry-run 및 실제 배포의 비동기 실행, job ID와 SSE 기반 진행 상태 표시
- Salesforce 테스트 실패, 스택 추적, 코드 커버리지 경고 상세 표시
- Apex 테스트 클래스 자동완성과 사용자별 테스트 클래스 접미사 설정
- 설정한 접미사에 맞는 테스트 클래스만 검색하는 후보 필터
- 선택한 target으로 바로 실행하는 실제 배포 UI
- 메타데이터 비교 병렬화와 retrieve 안정성 개선
- ADMIN 사용자 관리 및 실제 배포 권한·테스트 커버리지 검증

## 설치

GitHub Release에서 `sf-unlucky-deploy-0.2.0.tgz`와 `SHA256SUMS`를 내려받고 체크섬을 확인한다.

```bash
sha256sum --check SHA256SUMS
npm install --global --allow-scripts=sqlite3 ./sf-unlucky-deploy-0.2.0.tgz
sfud --version
```

실행에는 Node.js 20.19 이상과 Salesforce CLI v2가 필요하다. `sqlite3` native binding 설치 스크립트만 명시적으로 허용하며, 다른 의존성 스크립트는 허용하지 않는다.

## 배포 안전성

- CLI `deploy`는 `--execute`가 없으면 Salesforce check-only로 실행
- 웹 실제 배포는 ADMIN 권한과 대상 org 확인을 서버에서 재검증
- 선택한 source 컴포넌트만 실제 배포 payload에 포함
- Apex 배포는 지정 테스트와 클래스별 75% 커버리지 기준 검증
- 장시간 작업의 불확실한 종료 상태는 `RECONCILE_REQUIRED`로 보존
- destructive manifest 자동 생성 및 삭제 미지원

## 알려진 제한

- SQLite와 단일 프로세스 큐를 사용하므로 다중 인스턴스 수평 확장 미지원
- Salesforce CLI 인증과 org 별칭은 실행 호스트에서 별도로 준비 필요
- 실제 배포 전 대상 org와 선택 컴포넌트를 사용자가 확인해야 함
