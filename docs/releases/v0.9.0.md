# sf-unlucky-deploy v0.9.0

Git·로컬 프로젝트·Salesforce Org의 메타데이터 비교를 중심으로 사용 안내를 재구성하고, Git·소스·비교·배포·인증의 모듈 경계를 분리한 마이너 버전.

이 문서는 canary 병합을 위한 릴리스 준비 기록이다. 태그·GitHub Release·npm 발행 및 실제 Org 배포 완료를 의미하지 않는다.

## 사용자 변경 사항

- README에서 비교 대상별 활용 사례, Git 브랜치 선택, 메타데이터 diff 확인, CLI 비교 리포트 순서로 안내. 검증·배포는 비교 결과를 Org에 반영할 때 사용하는 후속 기능으로 설명.
- 웹 UI의 실제 배포는 사전 Dry-run 없이 선택한 테스트 수준으로 바로 제출. Salesforce에서 요구하는 테스트는 실제 배포 과정에서 실행.
- 명시적으로 Dry-run을 실행하고 승인하는 경로는 유지. 검증한 파일·Org·테스트 계획 등의 적격성을 확인한 뒤 검증 ID로 Quick Deploy.

## 내부 구조

- Git 저장소·토큰·브랜치 관리는 Git 모듈이 소유하고, 소스 준비는 `SourceProvider` 계약으로 연결. 비교·배포 서비스의 Git 구현 직접 참조 제거.
- 소스 준비와 작업 실행 사이에 파일 사용권을 인계하고, 준비 실패 시 새로 만든 import 정리. 기존 소스 소유권·불변 출처 정보 유지.
- `DeploymentStateMachine`으로 상태 전이와 시간값 판단 분리. 기존 상태 종류·의미, 저장소의 트랜잭션·동시성 검사 유지.
- 인증 정책·세션 저장·HTTP 쿠키 및 CSRF 처리를 분리. 별도 인증 라이브러리 도입 없이 기존 scrypt·DB 세션 유지.
- CLI 출력·종료 코드와 비교·배포 실행 로직 분리. UI의 Git·비교·배포 기능을 workflow에서 조합.
- 공개 진입점과 모듈 의존 방향 검사 추가. `npm run check`에서 내부 구현 직접 참조·모듈 순환·브라우저의 서버 코드 참조 차단.

구조와 소유권은 [모듈 경계 문서](../module-architecture.md) 참고.

## 호환성과 업데이트

패키지·CLI 버전은 `0.9.0`. 기존 설정, SQLite 테이블·DB 버전, 암호화 키 및 저장된 인증정보 형식 유지. 공개 CLI 옵션과 HTTP 경로 유지. 소스 내부 파일 경로는 모듈별로 이동.

정식 발행 후 업데이트 전에 `sfud stop`으로 실행 중인 UI를 종료하고 홈 설정·DB를 백업한다. 기존 암호화 키는 계속 사용한다. 설치 채널과 명령은 [README](../../README.md) 참고.

## 검증 범위

canary PR의 CI 결과는 해당 PR에서 확인한다. 로컬 검증 결과는 PR 본문에 기록한다. Salesforce 동작 검증은 fixture 기반이며 실제 Org 배포를 실행한 기록은 아니다.
