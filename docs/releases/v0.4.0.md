# sf-unlucky-deploy v0.4.0

Git 원본 가져오기, 개인용 원격 접속, 배포 확인·설정 저장·작업 복구를 추가한 마이너 버전이다.
정식 npm 배포 대상은 `@trstyq/sf-unlucky-deploy@0.4.0`이다.

## 주요 변경 사항

- GitHub·GitLab·Bitbucket 저장소 연결, 토큰 암호화 저장, 브랜치·메타데이터 선택 및 비교 원본으로의 가져오기
- 비교 파일 수 설정, 대형 XML·하위 메타데이터 비교 및 원본 provenance 기록
- 배포 attempt, immutable payload digest, org 실행 권한과 실제 Salesforce 상태를 분리해 재제출을 방지하는 복구 흐름
- 배포 admission·저장 공간 한도와 전역 실행 lease로 동시 실행 제어
- 검증 성공한 validation ID만 Quick Deploy 대상으로 허용하는 자격 검사와 화면 안내
- 웹 콘솔의 Git 원본, 배포 상태, 접근 제어 화면과 API 계약 보강
- Git 저장소 루트·하위 DX 프로젝트 자동 탐색과 다중 후보 선택, 등록 브랜치의 실제 프로젝트 경로 저장·커밋 재확인
- Git 연결 별칭과 저장소 식별자 함께 표시, Windows Git 긴 경로 지원 및 작업 폴더 잠금 오류 정리 재시도
- `LOCAL=true` 개인용 실행과 접속 주소 분리, 원격 개인용 비밀번호 `SFUD_ACCESS_PASSWORD` 및 세션 보호
- 비루프백 HTTP에서도 검증·직접 배포 요청에 필요한 보안 난수 UUID 생성 지원
- `sfud setup` 최초 설정 안내와 `sfud doctor` 읽기 전용 환경 점검
- 사용자별 배포 설정 저장·불러오기·삭제, 실제 소스·대상 Org·컴포넌트·테스트를 확인하는 배포 직전 화면
- 오류 원인과 다음 조치 안내, 실행 기록의 작업 URL, 요청 ID를 유지하는 제출 결과 조회·재시도
- 사용자·탭별 선택 초안 저장·복원과 만료 처리, 병렬 소스 준비 실패 시 작업 폴더 조기 해제 방지
- 사용자 홈 설정·암호화 키 보존, Salesforce 연결·세션 관리 개선, 시작·운영 문서 정리
- 동일 앱에 SQLite native binding과 실행 의존성을 포함하는 Windows x64 번들 제공

## 설치

정식 발행 완료 후 버전을 지정해 설치한다.

```bash
npm install --global --allow-scripts=sqlite3 @trstyq/sf-unlucky-deploy@0.4.0
sfud --version
```

Windows x64 SQLite 포함 번들은 같은 패키지의 별도 버전으로 설치한다.

```powershell
npm install --global --ignore-scripts @trstyq/sf-unlucky-deploy@0.4.0-win32-x64.1
sfud --version
```

Node.js 22.19.0 이상, Salesforce CLI v2와 Git이 필요하다. 일반판은 `sqlite3` 설치 스크립트를 허용한다.
Windows 번들은 SQLite 바이너리를 동봉하며 `sfud --version`은 원본 앱 버전 `0.4.0`을 표시한다.
GitHub Release tarball을 직접 설치하는 경우 `SHA256SUMS` 또는 `windows-x64-0.4.0-SHA256SUMS`로 체크섬을 확인한다.

처음 설정할 때 `sfud setup`, 기존 설정을 점검할 때 `sfud doctor`를 사용한다.

## 업그레이드 및 원격 접속

- 데이터 디렉터리와 홈 설정을 백업한 뒤 업그레이드한다. 배포 설정과 초안을 위한 DB 마이그레이션 47·48이 포함된다. 이전 버전으로 복귀할 때는 백업한 DB와 설정을 함께 복원한다.
- `SFUD_TOKEN_SECRET`은 Git·Salesforce 인증 저장용 암호화 키다. 기존 값을 유지하며 접속 비밀번호와 구분한다.
- 내 PC 개인용은 `LOCAL=true`, `SFUD_UI_HOST=127.0.0.1`을 사용한다. 불필요한 공개 Origin·프록시·접속 비밀번호 설정은 제거한다.
- 원격 개인용은 `sfud config path`가 가리키는 설정 폴더의 `secrets.env`에 `SFUD_ACCESS_PASSWORD`를 12~128자로 설정하고 `sfud ui --host 0.0.0.0 --allow-remote --no-open`으로 실행한다.
- `LOCAL=true`에서도 원격 주소·공개 Origin·프록시 설정이 적용된다. 해당 설정이 있는데 비밀번호가 없으면 서버가 시작되지 않는다. 인터넷 공개 시 HTTPS 프록시를 사용한다.
- 개인용 원격 Salesforce 브라우저 OAuth 연결에는 UI 주소와 별도로 콜백 포트 전달이 필요하다. 자세한 설정은 [환경설정 안내](../configuration.md)를 참고한다.

## 검증 범위

정식 태그의 Release 워크플로에서 타입·단위·브라우저 검증과 동일 tarball의 Linux Node 22.19/24,
Windows Node 24, macOS ARM64 Node 24 설치 검사를 수행한다.
Windows 번들은 Node 22.19/24에서 외부 통신 차단·빈 캐시·오프라인 설치·UI·SQLite·재시작을 별도로 검증한다.
npm에는 검증된 GitHub Release와 바이트가 일치하는 파일을 발행한다.
실제 Salesforce Org 검증·배포 결과는 자동 검사와 구분하며, 이번 정식 버전의 결과는 릴리즈 준비 기록에 남긴다.

## 운영 시 참고

- Quick Deploy는 성공한 check-only validation ID와 동일 대상 org에서만 제출할 수 있다.
- Git access token은 평문으로 응답하거나 로그에 기록하지 않는다.
- SQLite와 단일 프로세스 큐 기반으로 다중 인스턴스 수평 확장은 지원하지 않는다.
