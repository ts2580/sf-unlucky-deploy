# sf-unlucky-deploy v0.8.0

Git 저장소 등록과 비교할 브랜치 선택을 분리하고, 최신 커밋 비교·Apex 테스트 설정·초안 복원·비교 결과 스크롤을 개선한 마이너 버전.

## 주요 변경 사항

- 계정으로 조회한 목록에서는 저장소만 연결하고 비교 및 배포 화면에서 브랜치 선택. Git 주소로 연결한 저장소와 같은 흐름 제공.
- 소스·타겟에 활성 저장소 연결마다 한 항목 표시. 과거 가져오기 이력의 중복 노출을 없애고 연결 삭제 시 선택 목록에서도 제거.
- 새 비교마다 선택한 브랜치의 최신 커밋 확인. 비교 완료 후 Dry-run·배포에는 해당 비교의 고정된 소스를 사용하여 검증 대상 유지.
- Git 연결 조회와 작업 공간 초기 조회의 응답 순서가 달라도 사용자의 선택 보존. 다른 연결 갱신 중 현재 브랜치 유지.
- 배포 대상에 ApexClass가 포함될 때만 Apex 테스트 설정 표시. 대상에 ApexClass가 없을 때는 제출 기본값을 사용하고, 초안에는 사용자가 설정한 테스트 수준·클래스 목록 보존.
- 저장된 배포 설정의 Git 소스·타겟을 선택창과 패널에 일치시켜 표시. 일반 선택으로 전환하면 저장 설정의 과거 항목 정리.
- 패키지 전체 제외 시 준비된 항목을 선택·해제하고 불필요한 패키지 재조회 방지.
- 비교 결과와 파일 목록에 내부 스크롤 적용. 페이지·검색 조건·결과 전환 시 스크롤 초기화 및 데스크톱·모바일 페이지 높이 증가 문제 수정.

## 설치 및 전환

정식 발행과 registry 검증 완료 후 일반판 설치:

```bash
npm install --global --allow-scripts=sqlite3 @trstyq/sf-unlucky-deploy@0.8.0
sfud --version
sfud ui
```

SQLite 포함 Windows x64 번들의 예정 버전은 `0.8.0-win32-x64.1`. 일반판 산출물이 확정된 뒤 원본 커밋·SHA-256을 고정하고 별도 검증·발행.

```powershell
npm install --global --ignore-scripts @trstyq/sf-unlucky-deploy@0.8.0-win32-x64.1
sfud --version
sfud ui
```

Node.js 22.19.0 이상, Salesforce CLI v2와 Git 필요. Windows 번들의 CLI 버전은 `0.8.0`.
업데이트 전 실행 중인 UI를 `sfud stop` 또는 실행 터미널의 `Ctrl+C`로 종료하고 데이터 디렉터리와 홈 설정 백업.
기존 DB·암호화 키 유지. 과거 Git 가져오기 이력은 일반 선택 목록에서 숨기므로 저장소 연결을 선택하고 비교할 브랜치를 지정.

## 검증과 발행

정식 태그는 canary 검증과 사용자 수동 main PR 병합 후 최신 main에서 생성.
GitHub Release 워크플로에서 전체 검사와 Linux Node 22.19/24·Windows Node 24·macOS ARM64 Node 24의 동일 tarball 설치 검사 수행.
검증한 tarball·체크섬·SBOM·manifest를 Release에 첨부하고 동일 파일을 npm `next`로 발행.
Windows 번들의 Node 22.19/24 오프라인 검사 및 두 산출물의 registry 바이트 검증 후 일반판 `latest` 승격.

이 문서는 발행 준비 안내이며 배포 완료 기록은 아님. 현재 준비 상태와 선행 PR은 [0.8.0 릴리스 준비](v0.8.0-preparation.md)에 기록.
